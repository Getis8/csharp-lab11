# Крос-рев'ю, лабораторна №11 (структурні шаблони: Adapter, Facade, Proxy, Decorator)

Розподіл: Катя реалізувала Завдання 1-2 (Adapter, Facade), Стас реалізував Завдання 3-4 (Proxy, Decorator).
Рецензенти: Стас перевіряє Завдання 1-2, Катя перевіряє Завдання 3-4.

Критерії (з умови): діаграма відповідає коду; рішення усуває проблему з опису; раннер відтворює демонстраційний сценарій; у журналі видно, який об'єкт фактично виконує дію (обгортка чи обгорнутий).

## Завдання 1. Adapter (рецензент: Стас)

| Критерій | Що перевірено | Результат |
|---|---|---|
| Діаграма відповідає коду | `IFleetTelematics` (Target), `NativeTelematics`, `VendorTelematicsAdapter` (Adapter), `VendorTelematicsBlock` (Adaptee), `FleetMapView` (Client); зв'язок адаптера з блоком `_block`; метод `ToDecimalDegrees` статичний | ☐ |
| Рішення усуває проблему | Уся конвертація (DMS у градуси, літри у відсотки) в одному класі; `FleetMapView` не знає про виробника; блок виробника не змінено | ☐ |
| Раннер відтворює сценарій | Два авто на рідному інтерфейсі й одне через адаптер показані однаково; для `CE5678EE` очікується 48.2915, 25.9403, 50.0% | ☐ |
| У журналі видно, хто виконує | Записи `[Адаптер]` показують, що дані прочитано з блока виробника й переведено | ☐ |

| № | Зауваження | Статус |
|---|---|---|
| 1 | У початковій версії журнал не показував роботу адаптера (лише рядок карти). Додано логування в `GetPosition` і `GetFuelPercent` | ☐ виправлено |
| 2 | Записи `DmsCoordinate` і `GeoPoint` не винесені на діаграму, бо це допоміжні дані; за потреби додати | ☐ вирішено |

## Завдання 2. Facade (рецензент: Стас)

| Критерій | Що перевірено | Результат |
|---|---|---|
| Діаграма відповідає коду | `TripFacade` з шістьма підсистемами, константа `HoldAmount`, метод `StartTrip`; клієнти `MobileApp` і `DispatcherConsole` залежать від фасаду | ☐ |
| Рішення усуває проблему | Порядок кроків і правила описані один раз у `StartTrip`; застосунок і диспетчер не дублюють послідовність; підсистеми лишаються публічними (двері розблоковуються окремо) | ☐ |
| Раннер відтворює сценарій | Початок поїздки з застосунку, з консолі диспетчера й окреме віддалене розблокування дверей без поїздки | ☐ |
| У журналі видно, хто виконує | `[Фасад]` передає виконання, кожна підсистема пише у власний `[джерело]` | ☐ |

| № | Зауваження | Статус |
|---|---|---|
| 1 | Додано запис `[Фасад]` на початку `StartTrip`, інакше з журналу не було видно, хто керує порядком | ☐ виправлено |
| 2 | Якщо перевірка не пройдена після блокування коштів, розблокування не виконується; у вимогах цього немає, для захисту варто знати | ☐ прийнято |

## Завдання 3. Proxy (рецензент: Катя)

| Критерій | Що перевірено | Результат |
|---|---|---|
| Діаграма відповідає коду | `ICarControl` (Subject), `RemoteCarControl` (Real Subject), `CarControlProxy` (Proxy); поля `_real`, `_plate`, `_renter`, `_journal`; клієнт `DemoRunner` | ☐ |
| Рішення усуває проблему | Proxy має той самий інтерфейс, перевіряє орендаря й веде журнал; не орендар отримує відмову без звернення до сервера; застосунок про перевірки не знає | ☐ |
| Раннер відтворює сценарій | Команда орендаря йде на сервер, команда стороннього відхиляється, журнал команд, звернень до сервера 1 | ☐ |
| У журналі видно, хто виконує | `[Proxy]` приймає й вирішує, `[Сервер виробника]` з'являється лише для дозволеної команди | ☐ |

| № | Зауваження | Статус |
|---|---|---|
| 1 | Діаграма показувала клієнтом `MobileApp`, хоча в коді він залежить від `TripFacade`. Клієнта замінено на `DemoRunner` | ☐ виправлено |
| 2 | Порівняння `client != _renter` чутливе до регістру; для навчального проєкту прийнятно | ☐ прийнято |

## Завдання 4. Decorator (рецензент: Катя)

| Критерій | Що перевірено | Результат |
|---|---|---|
| Діаграма відповідає коду | `ITrip` (Component), `BasicTrip`, `TripOptionDecorator` (Decorator) з `Inner`, п'ять конкретних опцій | ☐ |
| Рішення усуває проблему | Опції вкладаються в будь-якій комбінації під час виконання; нова опція це один новий клас; класи під кожну комбінацію не потрібні | ☐ |
| Раннер відтворює сценарій | Звичайна (90.00), сімейна (4.60 грн/хв, 138.00), за місто (4.80 грн/хв, 144.00) | ☐ |
| У журналі видно, хто виконує | `[Базова поїздка]` і `[Опція «...»]` по черзі показують внесок обгорнутого об'єкта й кожної обгортки | ☐ |

| № | Зауваження | Статус |
|---|---|---|
| 1 | Початкова `CalculateCost` у декораторі не викликала обгорнутий об'єкт і нічого не логувала. Тепер вона рахує `Inner.CalculateCost() + Minutes * Surcharge` з записом у журнал | ☐ виправлено |
| 2 | Порядок обгорток не впливає на суму (надбавки адитивні); для захисту: це наслідок формули | ☐ прийнято |

## Підсумок

Діаграми відповідають коду після виправлень, вимоги з опису ситуацій виконано, раннери відтворюють сценарії. До захисту: підготувати відповіді на питання про різницю Adapter / Facade / Proxy / Decorator (див. розділ «Теорія» в гайді).
